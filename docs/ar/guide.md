# دليل Marsa بالعربي

Marsa (مَرسى) بيحوّل فولدر ملفات ثابتة لرابط عام بينتهي لوحده. مفيش حسابات: اللي معاه **مفتاح التعديل** هو اللي يقدر يدير الموقع.
الأمثلة بتستخدم `https://marsa.example.com` كعنوان للخدمة، ولما تقرأ الدليل جوه نسخة شغالة بيتبدّل بالعنوان الحقيقي.

## محتاج أنزّل حاجة؟

- **لو بتستخدم نسخة Marsa شغالة**: مش محتاج أي حاجة. ارفع من المتصفح أو استخدم الـ API.
- **لو هتشغّل نسختك**: محتاج Marsa بس، بأمر واحد: `docker compose up -d --build`. مفيش قاعدة بيانات ولا خدمات تانية، وكل مميزات النشر شغالة.
- **الـ backend الاختياري للبيانات والملفات** هو الحاجة الوحيدة اللي بتستخدم خدمة بره، وهي Cloudflare (Workers KV للبيانات وR2 للملفات)، وهو مقفول افتراضيًا. مش محتاج تنزّل حاجة، بتربط حساب Cloudflare بمتغيرات البيئة.

## الرفع من المتصفح

1. افتح الصفحة الرئيسية وانزل لـ **جرّب دلوقتي** (أو افتح `/ar/new`).
2. اسحب فولدر أو ملفات أو ملف `.zip`، أو استخدم **اختار ملفات** أو **اختار فولدر**.
3. اختار مدة الرابط (من ساعة لحد الحد الأقصى، 7 أيام افتراضيًا).
4. انسخ الرابط وابعته لأي حد.

المتصفح بيفتكر المواقع اللي رفعتها ومفاتيحها تحت **اللي رفعته من المتصفح ده**، فتقدر تمسحها بعدين من نفس المتصفح.

### شروط الموقع

- حط `index.html` في أول مستوى. لو كل الملفات جوه فولدر واحد، Marsa بيشيله لوحده.
- استخدم روابط نسبية (`css/style.css` مش `/css/style.css`)، لأن المواقع بتتعرض تحت `/s/<id>/`.
- ملف `404.html` في أول مستوى بيظهر للصفحات اللي مش موجودة.
- الملفات المخفية (`.env` و`.git/`) بتتشال، وسكريبتات السيرفر والبرامج (`.php` و`.py` و`.sh` و`.exe`...) بتترفض.

## الـ API

```bash
# ارفع ملف zip
(cd my-site && zip -qr ../site.zip .)
curl -s -X POST "https://marsa.example.com/api/sites?ttlHours=24" \
  -H "Content-Type: application/zip" --data-binary @site.zip

# أو ابعت الملفات كـ JSON
curl -s -X POST https://marsa.example.com/api/sites -H "Content-Type: application/json" \
  -d '{"ttlHours": 6, "files": [{"path": "index.html", "content": "<h1>أهلًا</h1>"}]}'
```

الرد فيه `url` و`expiresAt` و`id` و`editToken`. المفتاح بيظهر **مرة واحدة بس**، وMarsa بيخزّن الـ hash بتاعه بس، فلو ضاع مايترجعش.
المرجع الكامل بالإنجليزي في [API](/docs/api) وفي [`/openapi.json`](https://marsa.example.com/openapi.json).

## الإدارة بالمفتاح

```bash
TOKEN="marsa_…"; ID="k3v9x2mq7a"; BASE=https://marsa.example.com
curl -s -X PUT    "$BASE/api/sites/$ID" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/zip" --data-binary @site.zip   # تبديل كل الملفات
curl -s -X PATCH  "$BASE/api/sites/$ID" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"ttlHours": 48}'  # تغيير المدة
curl -s -X DELETE "$BASE/api/sites/$ID" -H "Authorization: Bearer $TOKEN"   # مسح فوري
```

الرابط عمره ما يعيش أكتر من وقت إنشاؤه + `MAX_TTL_HOURS`، مهما مدّيته. ولو انتهى، ارفعه تاني وخد رابط جديد.

## الـ AI agents

الخدمة بتقدّم تعليمات للـ agents على [`/llms.txt`](https://marsa.example.com/llms.txt). ودي رسالة تقدر تديها للـ agent:

```text
لما تعمل صفحة أو تقرير أو نموذج أولي محتاج أشوفه، انشره على Marsa بدل ما تبعتلي الـ HTML:
1. حط الملفات في فولدر فيه index.html، وبروابط نسبية بس. ماتحطش أسرار أو مفاتيح أو بيانات شخصية، لأن الرابط عام.
2. اضغط محتوى الفولدر:  (cd OUT_DIR && zip -qr ../site.zip .)
3. ارفعه:  curl -s -X POST "https://marsa.example.com/api/sites?ttlHours=24" -H "Content-Type: application/zip" --data-binary @site.zip
4. ابعتلي "url" و"expiresAt" من الرد، واحتفظ بـ "id" و"editToken" علشان التحديث أو المسح.
5. لو حصل خطأ، اقرأ error.code وصلّح الملفات وجرّب تاني.
```

أمثلة جاهزة بـ Shell وNode وPython في [دليل الـ agents](/docs/agents).

## استخدامات حقيقية

- **agent بيشارك تقرير HTML**: بدل ما يلزق كود، بيرجع رابط. المثال: `examples/agent-report`.
- **نموذج أولي لعميل**: ديمو للمراجعة من غير استضافة ولا حساب. المثال: `examples/client-prototype`.
- **صفحة إيفنت مؤقتة**: لمدة أسبوع بـ `ttlHours=168`. المثال: `examples/event-page`.
- **واجب دراسي**: الطلبة يسلّموا رابط. المثال: `examples/class-assignment`.
- **معاينة من الـ CI**: كل Pull Request ياخد رابط معاينة كتعليق. المثال: `examples/ci-preview`.

## تشغيل نسختك

```bash
docker compose up -d --build     # http://localhost:8080
```

أهم الإعدادات (متغيرات بيئة، والقيم الافتراضية في `.env.example`):

| المتغير | الافتراضي | المعنى |
| --- | --- | --- |
| `PUBLIC_URL` | `http://localhost:8080` | العنوان اللي بيتبني بيه الرابط |
| `DEFAULT_TTL_HOURS` / `MAX_TTL_HOURS` | `24` / `168` | مدة الرابط |
| `MAX_FILE_MB` / `MAX_SITE_MB` / `MAX_FILES` | `10` / `25` / `500` | حدود الحجم والعدد |
| `UPLOADS_PER_HOUR` | `20` | عدد الرفعات لكل IP في الساعة |
| `TRUST_PROXY` | `false` | خليه `true` لو ورا reverse proxy انت متحكم فيه |
| `ADMIN_TOKEN` | فاضي | لو اتحط، بيفتح `/api/admin/*` لإدارة كل المواقع |

التفاصيل الكاملة في [دليل الاستضافة](/docs/self-hosting).

## الـ backend الاختياري (Cloudflare)

لو صفحة أو agent محتاجين يخزّنوا بيانات صغيرة (KV) أو ملفات، Marsa يقدر يوصّلهم بـ Cloudflare: البيانات في Workers KV والملفات في R2، من غير Worker ولا تنزيل. كل البيانات مربوطة بالموقع وبتتمسح معاه.
- الكتابة محتاجة مفتاح التعديل دايمًا، والقراءة عامة طول ما الموقع شغال (`BACKEND_PUBLIC_READ=true`).
- الـ API token ومفاتيح R2 بيفضلوا على السيرفر، والمتصفح عمره ما بيشوفهم.
- الإعداد: اعمل API token في Cloudflare بصلاحيتين `Workers KV Storage: Edit` و`Workers R2 Storage: Edit`، وشغّل `CLOUDFLARE_ACCOUNT_ID=… CLOUDFLARE_API_TOKEN=… node scripts/cloudflare-setup.mjs --write-env .env`. السكريبت بيعمل الـ KV namespace والـ R2 bucket (أو بيستخدمهم لو موجودين)، وبيكتب `CLOUDFLARE_KV_NAMESPACE_ID` و`R2_BUCKET` و`R2_ACCESS_KEY_ID` و`R2_SECRET_ACCESS_KEY` في الملف. ومحتاج كمان `CLOUDFLARE_ACCOUNT_ID` و`CLOUDFLARE_API_TOKEN` في نفس الملف.
- من غيرهم، الـ routes دي بترد `503 BACKEND_NOT_CONFIGURED` والنشر شغال عادي.
- في الصفحة: `<script src="/sdk.js"></script>` وبعدين `marsa.kv.get("key")`.

التفاصيل بالإنجليزي في [دليل الـ backend](/docs/backend).

## الفرق ولوحة الأدمن

**دخول الفريق:** عضو الفريق يفتح `/ar/login` ويلصق **مفتاح الفريق**، فيدخل على لوحة الفريق `/ar/team`. الجلسة ملف cookie موقّع (`HttpOnly`) بيفضل 7 أيام أو لحد ما يخرج. من اللوحة يقدر:
- يشوف حالة الفريق: عدد المواقع الحيّة، وهل البيانات والملفات مفعّلة، وهل مواقعه بتظهر في الرئيسية.
- ينشر موقع جديد بالسحب والإفلات أو باختيار ملفات أو ملف zip أو فولدر، ويختار مدته.
- يدير كل موقع: يستبدل الملفات (الرابط نفسه)، ويمدّ المدة، ويخفيه من الرئيسية أو يظهره، ويمسحه، ويتصفّح قيم KV والملفات بتاعته ويمسح منها (لو الفريق له باك إند).
- ياخد أوامر جاهزة للـ agents بمكان للمفتاح (`$MARSA_TEAM_KEY`) من غير المفتاح الحقيقي.

**دخول المسؤول:** لو النسخة فيها `ADMIN_TOKEN`، افتح `/ar/admin/login` وحط رمز المسؤول (الجلسة 12 ساعة). من هناك تقدر:
- تعمل فريق وتاخد **مفتاح الفريق** (بيظهر مرة واحدة بس، والسيرفر بيحفظ الـ hash بتاعه بس).
- تحدد لكل فريق إذا كان ليه **وصول للباك إند** ولا لأ، وإذا كان **يظهر في الدليل العام** على الصفحة الرئيسية (شغال افتراضيًا).
- تعمل مفتاح جديد (القديم وجلساته بيبطلوا على طول) أو تمسح الفريق.
- تشوف **كل المواقع الحيّة** من الفرق والضيوف، وتصفّيها بفريق أو بالضيوف، وتمسح أي موقع.

كل الفورمات محمية بـ CSRF، ومحاولات الدخول ليها حد لكل IP، وتقدر تخرج في أي وقت.

الفريق بيرفع بالهيدر `X-Team-Key: <key>`. الرفع من غير مفتاح بيفضل زي ما هو (ضيف). مواقع الضيوف والفرق اللي من غير باك إند بترد `403 BACKEND_NOT_ALLOWED` على الـ KV والملفات، والفرق المسموح لها بترد `503 BACKEND_NOT_CONFIGURED` لحد ما الـ backend يتظبط (متغيرات Cloudflare).

الصفحة الرئيسية فيها قسم **منشورات الفرق**: لكل فريق عنوان، وتحته كروت بصورة لكل صفحة شغالة، ومعاها العنوان والرابط ووقت الانتهاء. وفوقها صفحة **مختارة** في كارت كبير. نفس البيانات على `GET /api/directory`. مفيش أي مفاتيح أو مواقع ضيوف بتظهر فيه.

**صورة الكارت:** مرسى مش بياخد سكرين شوت ومش بيحمّل حاجة من برّه، الصورة لازم تكون جوه الملفات اللي رفعتها. بياخد أول واحدة من دول:

1. ملف اسمه `cover.png` أو `cover.jpg` أو `cover.webp` (أو `.jpeg` / `.avif` / `.gif`) جنب `index.html`.
2. صورة `og:image` في `index.html`، لو بتشاور على ملف جوه الموقع.
3. أول `<img>` في `index.html` بتشاور على ملف جوه الموقع.

الصورة لازم تكون PNG أو JPEG أو WebP أو AVIF أو GIF (مش SVG)، وحجمها 2 ميجا بالكتير، وأحسن مقاس 1200×675. لو مفيش صورة، الكارت بيظهر رسمة فيها أول حرف من العنوان بلون الفريق. عشان تغيّر الصورة، ضيف `cover.png` واستبدل ملفات الموقع من لوحة الفريق (الرابط مش بيتغيّر)، والكارت بيتحدّث خلال 30 ثانية.

الصفحة المختارة بتتحدد من متغير السيرفر `FEATURED_SITES` (أرقام المواقع مفصولة بفاصلة). لو مش متحدد، بتظهر أحدث صفحة.

التفاصيل بالإنجليزي في [دليل الفرق](/docs/teams).

## المواقع الدائمة والحصص

عادةً كل رابط له مدة وبينتهي. لكن الفريق اللي الأدمن سامح له يقدر ينشر مواقع **دائمة**، ما بتنتهيش وما بتتمسحش تلقائيًا.

- **مين يقدر:** فيه خيار لكل فريق اسمه *دائم* في لوحة الأدمن. بيبقى شغال تلقائيًا للفرق اللي عندها باك إند (البيانات والملفات)، والأدمن يقدر يشغّله أو يقفله لأي فريق. الضيوف عمرهم ما يقدروا ينشروا موقع دائم.
- **النشر:** اختار **دائم (بلا انتهاء)** من قائمة المدة في لوحة الفريق، أو ابعت `?ttlHours=permanent` مع مفتاح الفريق.
- **التحويل:** زرار **اجعله دائمًا** في صفحة الموقع، أو `PATCH /api/sites/<id>` بـ `{"permanent": true}` ومعاه رمز التعديل. ولو عايز ترجّعه رابط مؤقت، اختار مدة واضغط **مدّد**.
- **الأدمن:** في صفحة كل المواقع فيه فلتر **المواقع الدائمة** وزرار **ألغِ الدوام**. لما الدوام يتلغي، الموقع بياخد المدة القصوى من وقتها عشان الفريق يلحق يتصرّف.

**الحصص:** كل فريق ليه حد أقصى للمواقع الشغالة (افتراضيًا 50) وللمساحة (افتراضيًا 200 ميجا)، سواء المواقع دائمة أو مؤقتة. الأدمن يقدر يغيّرهم لكل فريق من خانة *الحصة*. لو رفع جديد هيعدّي الحد، بيرجع `403 TEAM_QUOTA_EXCEEDED`، ولوحة الفريق بتعرض الاستهلاك.

## وصول MCP لكل مساحة

كل مساحة (موقع منشور) لها خادم MCP خاص بها على `https://marsa.example.com/mcp/s/<siteId>`، بنقل
Streamable HTTP، فلا يحتاج تثبيت أي شيء. يتصل الوكيل الذكي (Claude أو Cursor أو VS Code) برمز يعمل
لهذه المساحة وحدها.

- **الرموز:** تجدها في صفحة الموقع داخل لوحة الفريق، في قسم «وصول MCP». أعطِ الرمز اسمًا واختر
  صلاحيته:
  - **قراءة فقط:** معلومات الموقع، وقائمة الملفات، وقراءة ملف نصي حتى 256 KB. وإن كان للفريق
    backend فقراءة KV والملفات المرفوعة أيضًا.
  - **قراءة وكتابة:** تضيف استبدال ملفات الموقع على الرابط نفسه. وإن كان للفريق backend فتعديل
    KV ورفع الملفات وحذفها أيضًا.
- يظهر الرمز `marsa_mcp_…` **مرة واحدة** فقط، ويُحفظ منه الـ hash وحده. يمكنك إلغاؤه في أي وقت
  فيتوقف فورًا، ولكل مساحة 10 رموز بحد أقصى. يتوقف الرمز أيضًا عند انتهاء المساحة أو حذفها.
- أرسل الرمز في الترويسة `Authorization: Bearer marsa_mcp_…`. صفحة الموقع فيها إعدادات جاهزة
  للنسخ لـ Cursor وClaude Code وVS Code.
- **الحدود:** 60 طلبًا في الدقيقة لكل رمز، و60 عملية كتابة في الساعة لكل رمز، و500 كتابة KV في
  اليوم على مستوى الخادم كله، لأن خطة Cloudflare المجانية تسمح بـ 1000 كتابة يوميًا. تُغيَّر هذه
  الحدود بالمتغيرات `MCP_REQUESTS_PER_MINUTE` و`MCP_WRITES_PER_HOUR` و`MCP_KV_WRITES_PER_DAY`.

```bash
claude mcp add --transport http marsa-<siteId> \
  https://marsa.example.com/mcp/s/<siteId> \
  --header "Authorization: Bearer marsa_mcp_…"
```

التفاصيل الكاملة في [MCP per space](../mcp.md).

## أعضاء الفريق والأدوار

الفريق ممكن يكون فيه لحد 50 عضو، ولكل واحد دخول خاص بيه، من غير أي إيميل.

- **الدعوة:** المسؤول أو أي مالك يعمل **رابط دعوة** بيشتغل مرة واحدة، ومدته يوم أو 3 أيام أو 7 أيام. المالك بيعمله من صفحة «الأعضاء» (`/ar/team/members`)، والمسؤول من لوحة الإدارة أو من `POST /api/admin/teams/<id>/invites`. الرابط بيظهر مرة واحدة، وانت اللي بتبعته بنفسك.
- اللي يفتح الرابط بيختار اسم مستخدم واسم يظهر للناس وكلمة مرور (10 حروف على الأقل). بعدها الدعوة بتتلغي ويدخل على طول.
- **الأدوار:**
  - **مالك:** كل حاجة، ومنها إدارة الأعضاء والدعوات.
  - **محرّر:** ينشر المواقع ويستبدلها ويمدّدها ويخفيها ويمسحها، ويعمل رموز MCP.
  - **مشاهد:** قراءة بس.
- كلمات المرور بتتحفظ hash بخوارزمية scrypt بس. ولكل عضو جلساته: تغيير كلمة المرور أو «اخرج من كل الأجهزة الأخرى» بيقفل باقي الجلسات. ولو العضو اتشال، جلساته بتقفل فورًا.
- **مفتاح الفريق شغال زي ما هو:** الـ agents والـ API بيستخدموا `X-Team-Key` من غير أي تغيير، والدخول بالمفتاح في المتصفح بيشتغل كمالك. يعني الفرق الموجودة مش محتاجة أي ترحيل. ننصح تعمل لنفسك حساب مالك بدعوة، وتسيب المفتاح للـ agents.
- **سجل النشاط:** كل تغيير بيتسجّل باسم اللي عمله (عضو، أو مفتاح الفريق، أو رمز التعديل، أو المسؤول، أو رمز MCP). صفحة الموقع بتعرض آخر 30 حاجة حصلت عليه، وصفحة «الأعضاء» بتعرض آخر 100 للفريق كله.

## الوركرز للفرق (Cloudflare Workers)

الفريق يقدر ينشر وركرز صغيرة على كلاودفلير (API أو webhook أو خادم MCP) من خلال المساحات. المسؤول بيحط **مفتاح كلاودفلير واحد** للمنصة كلها، والمساحات هي اللي بتنشر بالنيابة عن الفرق، فـ**ولا فريق ولا إيجنت بيشوف المفتاح أو يحتاجه**.

- **المسؤول مرة واحدة:** من لوحة الإدارة ← «الوركرز» يحط مفتاح API (صلاحيات Workers Scripts: Edit على الحساب، وWorkers Routes: Edit وDNS: Edit على النطاق) والنطاق `marsaplatform.com`. المفتاح بيتشفّر على السيرفر (AES-256-GCM بالمتغير `MARSA_SECRETS_KEY`) وللكتابة بس: اللوحة بتعرض آخر 4 حروف وزرار «تحقّق» بس، ومفيش API بيرجّعه.
- **لكل فريق:** المسؤول يفعّل «الوركرز» ويدّي الفريق اسم مختصر (slug) زي `sanad`، وحد أقصى (الافتراضي 3 وركرز و1024 كيلوبايت للسكربت).
- **الأسماء إجبارية:** وركر اسمه `hello` لفريق `sanad` بيبقى السكربت `team-sanad-hello` على `https://sanad-hello.marsaplatform.com`.
- **الأمان:** المساحات بتعدّل أو تمسح بس الحاجات اللي هي عملتها. ولو اسم السكربت أو الدومين مستخدم قبل كده، بترفض (`409`) ومش بتلمسه.
- **الأدوار:** المالك والمحرّر ينشروا ويمسحوا من «لوحة الفريق ← الوركرز»، والمشاهد يتفرّج بس. الإيجنت بيستخدم مفتاح الفريق أو رمز MCP للمساحة بصلاحية قراءة وكتابة (أدوات `list_workers` و`deploy_worker` و`delete_worker`).
- لو المسؤول قفل الوركرز لفريق أو مسح الفريق، كل وركرز الفريق بتتمسح (الـ route والـ DNS والسكربت). وكل نشر أو مسح بيتسجّل في سجل النشاط.

```bash
export MARSA_TEAM_KEY=marsa_team_…   # سري
curl -s -X PUT "https://marsa.example.com/api/teams/sanad/workers/hello" \
  -H "X-Team-Key: $MARSA_TEAM_KEY" \
  -H "Content-Type: application/javascript" --data-binary @worker.js
curl -s "https://marsa.example.com/api/teams/sanad/workers" -H "X-Team-Key: $MARSA_TEAM_KEY"
curl -s -X DELETE "https://marsa.example.com/api/teams/sanad/workers/hello" -H "X-Team-Key: $MARSA_TEAM_KEY"
```

ملف `worker.js` لازم يكون ES module واحد: `export default { async fetch(request, env) { … } }`. ولو عايز متغيرات أو أسرار ابعت JSON: `{"code": "…", "vars": {"NAME": "…"}, "secrets": {"KEY": "…"}}`. الأسرار للكتابة بس، وأسماؤها بس اللي بتظهر. التفاصيل كاملة في [Team Workers](../workers.md).

## عدد الزيارات

لوحة الفريق بتعرض لكل موقع عدد مشاهدات الصفحات في آخر 7 و30 يوم، مع رسم صغير. وصفحة الموقع فيها رسم لكل يوم وعدد تقريبي للزوار.

- العدّ بيتم على السيرفر نفسه: من غير cookies، ومن غير تخزين IP أو user agent، ومن غير أي طرف تالت.
- بنعدّ صفحات HTML بس (مش الصور ولا الـ CSS). برامج الزحف (bots)، ومعاينات الروابط (WhatsApp وTelegram وSlack…)، والـ prefetch مش بتتحسب.
- «الزوار» رقم تقريبي: جوه الساعة الواحدة، الزائر هو hash مختلف من (salt عشوائي بيتغيّر كل ساعة + الموقع + IP + user agent). الـ salt موجود في الذاكرة بس، والـ hash عمره ما بيتخزّن. لو المتصفح باعت Do Not Track أو GPC، بنعدّ المشاهدة من غير الزائر.
- الأرقام بتتجمّع في الذاكرة، وبتتكتب كل دقيقة في `sites/<id>/visits.json` جنب الموقع، وبتتمسح لما الموقع يتمسح. مش بتستخدم KV خالص.
- الأيام بتوقيت UTC، وبنحتفظ بآخر 90 يوم (`VISITS_RETENTION_DAYS`). ولو عايز تقفل العدّ: `VISITS=false`.

## إصدارات الوركرز ومفاتيح الوكلاء والإشعارات (0.14.0)

- كل نشر لوركر بيتحفظ كإصدار: الكود والمتغيرات وأسماء الأسرار بس (مش قيمها)، مين نشر وإمتى والحجم والبصمة SHA-256 وملاحظة. آخر 10 إصدارات لكل وركر.
- من صفحة الوركرز: **أعد النشر** بنقرة واحدة، و**الإصدارات** فيها «ارجع لهذا الإصدار» (بتأكيد) و«نزّل الكود».
- المتغيرات بقت لحد 32 كيلوبايت للمتغير و64 كيلوبايت للمجموع.
- **مفاتيح الوكلاء**: مالك الفريق بيعمل مفتاح لكل وكيل بصلاحيات محددة (`workers:read`، `workers:deploy`، `spaces:read`، `spaces:write`، `kv:read`، `kv:write`، `mcp`) وتاريخ انتهاء إجباري (لحد سنة). المفتاح بيظهر مرة واحدة وبيتحفظ كبصمة بس، وتقدر تلغيه في أي وقت.
- **رابط دعوة وكيل**: رابط مرة واحدة صالح 24 ساعة؛ الوكيل يفتحه يلاقي التعليمات، ويستلم مفتاحه بطلب POST مرة واحدة.
- **الإشعارات**: جرس فيه عدد غير المقروء للمالكين والأدمن، و Webhook اختياري (متوافق مع Slack وDiscord وموقّع بـ HMAC).
- التفاصيل: [Agent keys](/docs/agent-keys) وسياسة الخصوصية على [/ar/privacy](/ar/privacy).

## الوصفات ومفاتيح API للوركرز (0.14.0)

- **الوصفات**: أدلة خطوة بخطوة للوكلاء والناس (الهدف، متى تُستخدم، الخطوات، قالب، قائمة تحقق، أخطاء شائعة) بالعربية والإنجليزية. خمس وصفات مدمجة على `/ar/docs/recipes`، ووصفات خاصة بالفريق يكتبها المالكون والمحررون من صفحة «الوصفات» في اللوحة، ووصفات للمنصة يكتبها المسؤول. للوكلاء: `GET /api/recipes` و`/api/recipes/<slug>?lang=ar&format=md`، وفي MCP المساحة `list_recipes` و`get_recipe`.
- **مفاتيح API لمستخدمي الوركر**: من بطاقة الوركر ← «مفاتيح API» فعّلوا «طلب مفاتيح API»، فتضيف مساحات السرّين `MARSA_KEYS_URL` و`MARSA_KEYS_SECRET` للوركر. أنشئوا مفتاحًا لكل مستخدم بحدود في الدقيقة واليوم وأدوات مسموحة وانتهاء، وألغوه بنقرة، وراقبوا الاستخدام. في كود الوركر الصقوا المساعد من `/api/keys/helper.v2.js` واستدعوا `requireKey(request, env, { tool })` قبل أي عمل. يتحقق المساعد من كل طلب افتراضيًا (عدّ دقيق)، و`{ cache: 30 }` اختياري مع احتمال تجاوز بسيط للحد. التفاصيل في وصفة «احمِ خادم MCP بمفاتيح مساحات».

## صفحات التفاصيل والجداول (0.15.0)

- **صفحة الوركر** (`/team/workers/<name>`، وللأدمن `/admin/teams/<id>/workers/<name>`): نظرة عامة (الحالة، الرابط مع نسخ/فتح، عنوان MCP لو الكود فيه `/mcp`، آخر نشر ومين عمله، الحجم، SHA-256، أسماء المتغيرات والأسرار، فحص الصحة، الطلبات في آخر 7 أيام)، الإصدارات (رجوع وتنزيل)، مفاتيح API، الإعدادات (إلزام المفاتيح والحدود، تعديل المتغيرات، ضبط/حذف الأسرار، إيقاف/تشغيل، حذف بتأكيد)، والنشاط. تعديل المتغيرات أو الأسرار بيعيد نشر آخر كود ويتسجل كإصدار جديد. الوركر اللي الأدمن وقفه الأدمن بس يقدر يشغله.
- **صفحة الفريق للأدمن** (`/admin/teams/<id>`): إحصائيات، الأعضاء (تغيير الدور، الحذف)، المساحات، الوركرز، مفاتيح الوكلاء، الحصص والمزايا ومنها تفعيل الوركرز، النشاط، ومنطقة الخطر (مفتاح جديد، حذف).
- **صفحة المساحة** (`/team/sites/<id>`، وللأدمن `/admin/sites/<id>`): معاينة، فتح/نسخ الرابط، رسم الزيارات لـ 30 يوم، الملفات، متصفح KV والملفات المرفوعة، الدوام والانتهاء، توليد edit token جديد (بيظهر مرة واحدة)، MCP، النشاط، والحذف.
- **كل الجداول**: الصف كله بيفتح صفحة التفاصيل (بالماوس أو Enter)، أزرار أيقونات وقائمة ⋮ عليها أسماء، أعمدة أكتر، ترتيب وبحث وفلاتر وصفحات، ورسالة لما الجدول فاضي، وعرض كروت على الموبايل.

## استدعاء وركر لوركر تاني (0.15.0)

`fetch()` من وركر لعنوان على نفس النطاق (زي `sanad-news.marsaplatform.com`) بيروح للـ origin مش للوركر. عندكم حلّين:

- **ربط مباشر**: `"bindings": [{"name":"NEWS","worker":"news"}]`. في الكود: `env.NEWS.fetch(request)`. الربط مسموح بس مع وركرز نفس الفريق.
- **العَلَم** `global_fetch_strictly_public` في `compatibilityFlags`، وساعتها الطلب بيطلع على الإنترنت.

الأعلام المسموحة هي `global_fetch_strictly_public` و`nodejs_compat` و`nodejs_als`. تقدروا كمان تحددوا `compatibilityDate`. الإعدادات دي بتتحفظ مع كل إصدار. ولو عايزين تغيّروها من غير ما تبعتوا الكود: `POST …/workers/<name>/runtime`، أو أداة `set_worker_runtime`، أو تبويب الإعدادات.

## سيرفرات MCP والمستودعات وملاحظات الإيجنتس (0.15.1)

- **قالب جاهز**: ‏`/api/recipes/mcp-server-on-worker/starter.zip` (‏TypeScript + Hono + حزمة MCP الرسمية) يُبنى وينجح في اختباراته وفيه سكربت نشر بلا wrangler. التفاصيل في وصفة «سيرفر MCP على وركر في المساحات».
- **جداول الوركرز** تعرض النوع (سيرفر MCP / موقع أو API / غير ذلك) واللغة والتقنية وعدد أدوات MCP وحماية المفاتيح والمستودع، مع فلاتر. تُعلَن البيانات عند النشر (`meta` و`repo`)، أو تُستنتج من الكود، أو من فحص قراءة فقط لـ `tools/list`.
- **سيرفرات MCP**: عنصر في القائمة الجانبية يعرض كل وركر من نوع MCP، مع عنوانه وصفحة المساحة المرتبطة وحالة المفاتيح وزر «مفاتيح المستخدمين».
- **عمود المستودع** في جداول المساحات والوركرز: عام أو خاص أو غير موجود، ومتزامن أو متأخر عن الفرع. يُفحص على GitHub قراءةً فقط مع تخزين مؤقت.
- **ملاحظات الإيجنتس**: يترك الإيجنت ملاحظة عبر `POST /api/teams/<team>/notes` أو أداة MCP ‏`leave_note`. يراها المسؤول في «ملاحظات الإيجنتس» ويرد عليها أو يغلقها، والملاحظات العائقة تُنبّه الجرس. ويرى كل فريق ملاحظاته فقط.

## الخصوصية

- أي حد معاه الرابط يقدر يشوف الموقع.
- مفيش حسابات ولا cookies للتتبع ولا تحليلات من طرف تالت. عدد الزيارات بيتحسب على السيرفر نفسه كأرقام يومية بس.
- الـ IP بيستخدم في الذاكرة بس لحدود الاستخدام ولعدّ الزوار كل ساعة، ومش بيتسجّل. مع مفاتيح الوكلاء بنحفظ بصمة مفتاحية (HMAC) للـ IP بس عشان ننبّه لو المفتاح اتستخدم من عنوان جديد.
- الصفحات المرفوعة بتشتغل جوه sandbox ومتقدرش توصل للتطبيق.
