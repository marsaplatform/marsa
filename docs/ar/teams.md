# الفرق والوصول إلى الخلفية والدليل العام

لا توجد حسابات مستخدمين في مرسى. عندما يكون للنسخة `ADMIN_TOKEN`، يستطيع المشغّل إنشاء
**فرق** بدلًا من ذلك. يحصل كل فريق على **مفتاح فريق**، ويقرر المسؤول أمرين لكل فريق:

- **الوصول إلى الخلفية**: هل تستطيع مواقع الفريق استخدام مسارات KV والملفات الاختيارية
  (`/api/sites/:id/kv` و`/api/sites/:id/files`)؟
- **الظهور في الدليل العام** (مفعّل افتراضيًا): هل تُدرج مواقع الفريق الحية في الصفحة الرئيسية؟

رفع الضيوف (بلا مفتاح فريق) يعمل تمامًا كما كان. لا يحصل أبدًا على وصول إلى الخلفية ولا
يُدرج أبدًا.

## تسجيل الدخول

لمرسى Spaces طريقتا دخول في المتصفح. كلتاهما تنشئ **كوكي جلسة موقّعة** (HMAC-SHA256 بـ
`SESSION_SECRET`، و`HttpOnly`، و`Secure` على HTTPS مع البادئة `__Host-`، و`SameSite=Lax`، فالروابط
من مواقع أخرى إلى اللوحة تُبقيك مسجّلًا). نماذج الدخول تستخدم كوكي CSRF منفصلة قصيرة العمر
مع `SameSite=Strict`؛ وكل إرسال نموذج يحمل أيضًا رمز CSRF. لا يُحفظ أي مفتاح أو رمز في
المتصفح.

| من | أين | بماذا | الجلسة |
| --- | --- | --- | --- |
| عضو الفريق | `/login` (بالعربية `/ar/login`) | اسم المستخدم + كلمة المرور (انظر [الأعضاء](#الأعضاء-والأدوار-وسجل-التدقيق)) | `SESSION_TTL_HOURS` (الافتراضي ٧ أيام) |
| الفريق (بديل المالك) | `/login`، *أو استخدم مفتاح الفريق* | مفتاح الفريق | `SESSION_TTL_HOURS` |
| المسؤول | `/admin/login` (بالعربية `/ar/admin/login`) | `ADMIN_TOKEN` | `ADMIN_SESSION_TTL_HOURS` (الافتراضي ١٢ ساعة) |

- محاولات الدخول محدودة لكل IP (`LOGIN_ATTEMPTS_PER_15_MIN`، الافتراضي ١٠).
- كل نموذج يغيّر شيئًا يحمل رمز CSRF مرتبطًا بالجلسة، ويجب أن يأتي الطلب
  من هذه النسخة (Origin / `Sec-Fetch-Site`). الصفحات المرفوعة تعمل في عزل ولا تستطيع استخدام
  الجلسة.
- **تسجيل الخروج** ينهي الجلسة فورًا. تدوير مفتاح الفريق أو حذف الفريق يُخرج أعضاءه؛
  وتغيير `ADMIN_TOKEN` أو `SESSION_SECRET` يُخرج الجميع.
- بدون `SESSION_SECRET` يُولَّد سر عشوائي عند البدء، فتنتهي الجلسات عند كل إعادة تشغيل.
  اضبط واحدًا في الإنتاج: `openssl rand -hex 32`.

## الأعضاء والأدوار وسجل التدقيق

يمكن أن يكون للفريق حتى ٥٠ **عضوًا**، لكل منهم دخول شخصي. لا بريد إلكتروني في الأمر.

**الدعوة.** ينشئ المسؤول، أو أي مالك، **رابط دعوة لمرة واحدة** ينتهي بعد ٢٤
ساعة أو ٣ أيام (الافتراضي) أو ٧ أيام. المالكون يفعلون ذلك من *الأعضاء* (`/team/members`)؛ والمسؤول يستخدم
اللوحة (عمود *الأعضاء* ← *إنشاء رابط دعوة*) أو الـ API. يُعرض الرابط مرة واحدة، وترسله
إلى الشخص بنفسك. من يفتحه أولًا يختار:

- **اسم مستخدم**: من ٣ إلى ٣٢ حرفًا (`a-z 0-9 . _ -`)، فريد على النسخة؛
- **اسمًا ظاهرًا**؛
- **كلمة مرور**: ١٠ أحرف على الأقل، لا تحتوي اسم المستخدم.

تُستهلك الدعوة ويُسجَّل دخوله. الروابط المستخدمة أو الملغاة أو المنتهية تُعيد
`404`. حد أقصى ٢٠ دعوة معلّقة لكل فريق.

**الأدوار**

| الدور | يستطيع |
| --- | --- |
| مالك | كل شيء، بما في ذلك الدعوة وتغيير الأدوار وإزالة الأعضاء |
| محرر | نشر المواقع واستبدالها وتمديدها وجعلها دائمة وإدراجها أو إخفاؤها وحذفها؛ مفاتيح MCP؛ حذف مفاتيح KV والملفات المرفوعة |
| مشاهد | قراءة فقط: المواقع وعدد الزيارات والملفات و KV ونقطة MCP والنشاط |

يفرض الخادم الأدوار في كل طلب، وتخفي الصفحات ما لا يستطيعه الدور. تغيير الأدوار
والإزالة يسريان فورًا، وتنتهي جلسات العضو المُزال.

**كلمات المرور والجلسات**

- تُجزَّأ كلمات المرور بـ **scrypt** (N=2¹⁵، r=8، p=1، ملح ١٦ بايت) وتُحفظ كبصمة فقط.
  رموز الدعوة تُحفظ كبصمة SHA-256 فقط.
- محاولات الدخول محدودة، واسم المستخدم غير المعروف يستغرق في الفحص وقت كلمة المرور الخاطئة نفسه.
- لكل عضو جلساته الخاصة. *تغيير كلمة المرور* و*تسجيل الخروج من كل مكان آخر* (في
  *الأعضاء* ← *حسابك*) ينهيان جلسات العضو الأخرى.
- لا استعادة عبر البريد. إذا نسي عضو كلمة مروره، يزيله مالك ويرسل له
  دعوة جديدة.

**مفتاح الفريق ما زال يعمل.**

- الوكلاء والسكربتات و CI يستمرون في استخدام `X-Team-Key` مع الـ API دون تغيير.
- الدخول بمفتاح الفريق في المتصفح (*أو استخدم مفتاح الفريق* في `/login`) يعمل
  **كمالك**، فتستمر الفرق الحالية بالعمل دون خطوة ترحيل. تبدأ الفرق بلا أعضاء.
- المستحسن: ادعُ نفسك كمالك واستخدم ذلك الحساب يوميًا. احتفظ بالمفتاح
  للوكلاء. إذا دوّرت المفتاح تنتهي جلساته في المتصفح ويحتاج الوكلاء المفتاح الجديد، لكن حسابات
  الأعضاء لا تتأثر.

**سجل التدقيق.** تُسجَّل التغييرات مع من قام بها: اسم العضو، أو *مفتاح الفريق*، أو *مفتاح التعديل*،
أو *المسؤول*، أو اسم مفتاح MCP. يشمل ذلك النشر والاستبدال وتغيير الانتهاء والدوام
والإدراج والحذف ومفاتيح MCP وحذف KV والملفات والدعوات والانضمام وتغيير الأدوار والإزالة
وتغيير كلمات المرور، و(0.16.0) كل تغيير من المسؤول: إنشاء الفرق وتحديثها وحذفها، والحدود والميزات،
وإلغاء الدعوات، وحذف المواقع ودوامها، والتنظيف، والوصفات، والملاحظات، وفترة الفحص، وإعادة فحص
صلاحيات المفتاح، والـ Webhooks، والنسخ الاحتياطي، وتسجيل الخروج من كل مكان. تعرض صفحة الموقع آخر ٣٠ مدخلًا
لذلك الموقع تحت *النشاط على هذا الموقع*، وتعرض *الأعضاء* آخر ١٠٠ للفريق. يُحفظ آخر ٥٠٠
مدخل لكل فريق في `<DATA_DIR>/audit.json`.

**API النشاط والتنزيلات (0.16.0).** `GET /api/teams/<team>/activity` (مفتاح الفريق فقط؛ مفاتيح الوكلاء
تحصل على `403 TEAM_KEY_REQUIRED`) و`GET /api/admin/activity?team=<id|platform>` (المسؤول؛ بدون `team` = كل
السجلات) يُعيدان `{entries, count}`، الأحدث أولًا. المرشحات: `since` / `until` (وقت ISO أو ميلي ثانية)،
و`action` (مطابق تمامًا، أو بادئة تنتهي بـ `-` مثل `worker-`)، و`site`، و`limit` (الافتراضي ٥٠٠، والأقصى ٥٠٠٠).
`format=csv` أو `format=jsonl` ينزّل الصفوف نفسها (CSV بترميز UTF-8 مع BOM؛ والخلايا التي تبدأ بـ
`=` أو `+` أو `-` أو `@` تُسبق بـ `'`). في صفحات النشاط زرّا *CSV* و*JSONL*.

**تصدير الفريق (0.16.0).** ينزّل المالكون كل ما للفريق على Spaces من *الإعدادات ← تصدير
الفريق*، أو بـ `GET /api/teams/<team>/export` (مفتاح الفريق). في الـ zip المواقع وملفاتها، و
الوركرات بإصداراتها، و KV والملفات المرفوعة، والأعضاء (بلا كلمات مرور)، ومفاتيح الوكلاء (بلا أسرار)، و
سجل النشاط. لا يُضمَّن أي مفتاح أو رمز أو سر. الأعضاء والدعوات في `<DATA_DIR>/members.json` (بصلاحية 600). حذف
فريق يحذف أعضاءه ودعواته وسجله.

API الإدارة:

```bash
# Invite (role owner|editor|viewer, default owner; ttlHours 1-168, default 72)
curl -s -X POST "$BASE/api/admin/teams/t_abc123/invites" -H "$AUTH" \
  -H "Content-Type: application/json" -d '{"role":"editor","ttlHours":72}'
# -> {"invite":{...},"url":"https://marsa.example.com/join/marsa_inv_..."}
curl -s "$BASE/api/admin/teams/t_abc123/members" -H "$AUTH"   # members + pending invites
curl -s -X DELETE "$BASE/api/admin/teams/t_abc123/members/m_xyz" -H "$AUTH"
curl -s -X DELETE "$BASE/api/admin/teams/t_abc123/invites/<inviteId>" -H "$AUTH"
```

## لوحة الفريق

بعد تسجيل الدخول يصل عضو الفريق إلى `/team` (أو `/ar/team`):

- **الحالة**: اسم الفريق، وعدد المواقع الحية، وهل *البيانات والملفات* مفعّلة للفريق (وهل
  للخادم خلفية مُعدّة)، وهل الفريق مدرج في الصفحة الرئيسية.
- **قائمة البدء** (0.16.0): خطوات الإعداد الأولى (نشر أول مساحة، دعوة عضو، مفتاح وكيل، وركر)، تختفي عند اكتمالها أو إخفائها.
- **المواقع الحية**: العنوان والرابط والانتهاء والحجم والظهور في الصفحة الرئيسية، مع **إدارة** و**حذف**.
- **نشر موقع جديد**: اسحب ملفات أو مجلدًا أو ملف `.zip` واحدًا وأفلته، أو اخترها، ثم اختر متى
  ينتهي (ضمن حدود النسخة).
- **تفاصيل المساحة** (`/team/sites/<id>`، 0.15.0): تبويبات **نظرة عامة** (معاينة، ونسخ الرابط أو فتحه،
  و**تمديد** الانتهاء — ولا يتجاوز الإنشاء + `MAX_TTL_HOURS` — والدوام، والظهور في الصفحة الرئيسية)،
  و**الزيارات** (رسم ٣٠ يومًا)، و**الملفات**، و**البيانات** (للفرق التي لها وصول إلى الخلفية، متصفح لقيم
  KV والملفات المرفوعة: عرض وحذف)، و**MCP**، و**النشاط**، و**الإعدادات**
  (استبدال الملفات بالرابط نفسه، وإعادة توليد مفتاح التعديل — يُعرض مرة واحدة — والحذف).
- كل صف في جدول يفتح صفحة تفاصيله (انقر، أو ركّز عليه واضغط Enter)؛ الإجراءات أزرار أيقونات
  إضافة إلى قائمة ⋮ موسومة. للجداول بحث ومرشحات وترتيب وتقسيم صفحات وعرض بطاقات على
  الهواتف.
- **البحث الشامل** (0.16.0): اضغط ⌘K (أو Ctrl+K، أو `/`) في أي صفحة من اللوحة للبحث في المساحات والوركرات وخوادم MCP والملاحظات والتوثيق.
- **مقتطفات للوكلاء**: استدعاء `curl` وتعليمات تستخدم `$MARSA_TEAM_KEY` (وليس المفتاح الحقيقي أبدًا).

مواقع الفريق تُدار عبر الجلسة: لا يحتاج أحد في الفريق مفتاح التعديل لكل موقع.
لكل موقع مفتاح رغم ذلك (تُحفظ بصمته فقط)، فتستمر السكربتات في استخدام `PUT/PATCH/DELETE
/api/sites/:id` بالمفتاح المُعاد وقت الرفع. المواقع التي نشرها فريق عبر الـ API مع
`X-Team-Key` تظهر في لوحته أيضًا.

## لوحة الإدارة

سجّل الدخول من `/admin/login` بـ `ADMIN_TOKEN`. في الشريط الجانبي خمس صفحات:

1. **نظرة عامة** (`/admin`): إجماليات المنصة (الفرق والمساحات والوركرات والمشاهدات) وجدول الفرق.
   أنشئ فريقًا (الاسم، و*البيانات والملفات*، و*في الصفحة الرئيسية*، و*دائم*). **يُعرض مفتاح الفريق
   مرة واحدة** بعد الإنشاء أو التدوير؛ تحفظ مرسى بصمته SHA-256 فقط. لكل صف مفاتيح تبديل لـ
   *البيانات والملفات* و*في الصفحة الرئيسية* و*دائم* و*الوركرات*، والحصص، وقائمة **المزيد** فيها
   **دعوة** و**مفتاح جديد** (يتوقف المفتاح القديم وجلساته فورًا) و**حذف** (اختياريًا
   مع مواقعه؛ وإلا تبقى كروابط عادية حتى تنتهي). انقر فريقًا لفتح
   **صفحة تفاصيله** (`/admin/teams/<id>`، 0.15.0): الإحصاءات، والأعضاء (تغيير الدور، الإزالة)، والمساحات،
   والوركرات، ومفاتيح الوكلاء (الإلغاء)، والحصص والميزات (بما فيها الوركرات)، والنشاط، ومنطقة الخطر.
2. **المساحات** (`/admin/sites`): كل موقع حي مع مالكه (فريق أو *ضيف*) ورابطه وانتهائه
   وحجمه. صفِّ حسب الفريق أو الضيوف أو الدائم، وابحث، ورتّب، واحذف أي موقع. الصف يفتح
   `/admin/sites/<id>` (التبويبات نفسها كصفحة الفريق).
3. **الوركرات** (`/admin/workers`): إعدادات الوركرات لكل فريق وكل وركرات الفرق.
4. **النشاط** (`/admin/activity`): سجل نشاط كل فريق إضافة إلى سجل المنصة، مع التصفية حسب
   الفريق ونوع الفاعل والنص، وتنزيلات CSV/JSONL.
5. **الإعدادات** (`/admin/settings`): اتصال Cloudflare لوركرات الفرق (مفتاح للكتابة فقط،
   تظهر آخر ٤ أحرف منه) وإعدادات الخادم.

للوحة الفريق التخطيط نفسه: **نظرة عامة** و**المساحات** و**الوركرات** و**الأعضاء** و
**النشاط** و**الإعدادات** (كلمة مرورك، وتسجيل الخروج من كل مكان، وتصدير الفريق).

## الرفع كفريق

أرسل مفتاح الفريق مع الرفع، في `X-Team-Key` (أو `Authorization: Bearer <team key>`):

```bash
curl -s -X POST "https://marsa.example.com/api/sites?ttlHours=72" \
  -H "X-Team-Key: $TEAM_KEY" \
  -H "Content-Type: application/zip" --data-binary @site.zip
# => { "id": "…", "url": "…", "editToken": "…", "team": { "id": "t_…", "name": "…", "backend": true }, … }
```

- مفتاح الفريق الخاطئ أو المُدوَّر يُعيد `401 INVALID_TEAM_KEY` (لا يتحول بصمت إلى ضيف أبدًا).
- يُدار الموقع من لوحة الفريق، أو بـ **مفتاح التعديل** الخاص به عبر الـ API. مفتاح الفريق
  نفسه للإنشاء وتسجيل الدخول فقط.
- `<title>` في `index.html` يصبح عنوان البطاقة في الدليل (وإلا معرّف الموقع).

## المواقع الدائمة والحصص

افتراضيًا ينتهي كل رابط (من ساعة واحدة حتى `MAX_TTL_HOURS`). الفريق الذي يسمح له المسؤول يستطيع أيضًا نشر
مواقع **دائمة** لا تنتهي ولا تُنظَّف أبدًا.

- **من:** علامة *دائم* لكل فريق (لوحة الإدارة، أو `"permanent": true` في API الإدارة). قيمتها
  الافتراضية تتبع وصول الفريق إلى *البيانات والملفات* (الخلفية)، لأن هذه هي الفرق التي تشغّل
  تطبيقات حقيقية؛ ويستطيع المسؤول تشغيلها أو إطفاءها لأي فريق. الضيوف لا يستطيعون أبدًا نشر مواقع دائمة.
- **النشر دائمًا:** اختر **دائم (بلا انتهاء)** في منتقي الانتهاء في اللوحة، أو أرسل
  `?ttlHours=permanent` (أو `?permanent=1`، أو `"ttlHours": "permanent"` / `"permanent": true` في
  رفع JSON) مع مفتاح الفريق.
- **التحويل:** **اجعله دائمًا** في صفحة الموقع، أو `PATCH /api/sites/<id>` مع
  `{"permanent": true}` ومفتاح التعديل. لجعله رابطًا مؤقتًا من جديد اختر مدة واضغط
  **تمديد** (أو `PATCH` مع `{"ttlHours": N}`)؛ ثم يُحسب عمره الأقصى من تلك اللحظة.
- **المسؤول:** في *كل المواقع* مرشح **المواقع الدائمة** وزر **إلغاء الدوام**؛ والـ
  API هو `PATCH /api/admin/sites/<id>` مع `{"permanent": false}` (أو `true` لأي موقع فريق).
  الموقع الذي أُلغي دوامه يحصل على `MAX_TTL_HOURS` من الآن، فيكون لفريقه وقت للتصرف.
- في الـ API للموقع الدائم `"permanent": true` و`expiresAt` بقيمة `9999-12-31T00:00:00.000Z`
  (تاريخ حقيقي، فتستمر العملاء التي تقارن التواريخ بالعمل).

**الحصص** تمنع الدوام من أن يعني بلا حدود. لكل فريق حد أقصى `TEAM_MAX_SITES` موقعًا
حيًا (الافتراضي ٥٠) تستخدم إجمالًا `TEAM_MAX_MB` على الأكثر (الافتراضي 200 MB)، دائمة أو لا. يستطيع المسؤول
تغيير الاثنين لكل فريق (حقول *الحصة* في اللوحة، أو `maxSites` / `maxMb` في API
الإدارة؛ القيمة الفارغة أو `0` أو `null` تعيد الافتراضي). الرفع أو الاستبدال الذي يتجاوزها يُعيد
`403 TEAM_QUOTA_EXCEEDED`؛ وتعرض اللوحة استهلاك الفريق. رفع الضيوف محدود كما كان
(حدود الحجم، والرفع في الساعة، وينتهي).

اضبط الحصص على حجم قرصك: يجب أن تتسع حصص كل الفرق معًا في وحدة البيانات مع مجال لرفع
الضيوف.

## عدد الزيارات

تعرض اللوحة مشاهدات صفحات كل موقع في آخر ٧ و٣٠ يومًا، مع رسم مصغّر. صفحة الموقع
تضيف رسمًا يوميًا وعددًا تقريبيًا للزوار. *كل المواقع* في لوحة الإدارة تعرض
الأرقام نفسها لكل موقع.

- **خاص بالتصميم.** يتم العدّ على هذا الخادم: لا كوكيز، ولا تُحفظ عناوين IP أو وكلاء المستخدم،
  ولا أطراف ثالثة، ولا شيء يُضاف إلى الصفحات المنشورة.
- **ما يُحسب:** طلبات `GET` الناجحة لصفحات HTML تحت `/s/<id>/`. الملفات المساعدة لا تُحسب،
  ولا الروبوتات، ولا جالبو معاينات الروابط (WhatsApp و Telegram و Slack…)، ولا المتصفحات بلا واجهة، ولا
  السكربتات (`curl` و`python-requests`…)، ولا الجلب المسبق.
- **الزوار (تقريبيًا):** خلال ساعة UTC واحدة، الزائر هو قيمة مميزة من `sha256(hourly salt + site +
  IP + user agent)`. الملح عشوائي، محفوظ في الذاكرة فقط ويُستبدل كل ساعة، فلا يمكن ربط البصمات
  عبر الساعات أو إعادة حسابها لاحقًا. تُحفظ المجاميع اليومية فقط، فالشخص الذي يعود في ساعة
  لاحقة يُحسب مجددًا. مع Do Not Track أو Global Privacy Control تُحسب الزيارة
  كمشاهدة فقط.
- **التخزين:** تُخزَّن الأعداد مؤقتًا في الذاكرة وتُكتب كل `VISITS_FLUSH_SECONDS` (٦٠ ثانية)، وعند
  الإيقاف، إلى `sites/<id>/visits.json` بصيغة `{"v":1,"days":{"YYYY-MM-DD":[views,visitors]}}`.
  - لا تلمس أبدًا خلفية KV وحد كتابتها اليومي.
  - تُحذف الأيام الأقدم من `VISITS_RETENTION_DAYS` (٩٠).
  - حذف موقع أو انتهاؤه يحذف أعداده.
- إذا تعطل الخادم قد تضيع أعداد فترة كتابة واحدة على الأكثر. اضبط `VISITS=false` لإيقاف
  العدّ.

## من يستطيع استخدام الخلفية

| الموقع | الخلفية مُعدّة | الخلفية **غير** مُعدّة |
| --- | --- | --- |
| فريق له وصول إلى الخلفية | تعمل (مفتاح التعديل للكتابة) | `503 BACKEND_NOT_CONFIGURED` |
| فريق بلا وصول إلى الخلفية | `403 BACKEND_NOT_ALLOWED` | `403 BACKEND_NOT_ALLOWED` |
| رفع ضيف | `403 BACKEND_NOT_ALLOWED` | `403 BACKEND_NOT_ALLOWED` |

يجري الفحص في كل طلب، فإطفاء وصول فريق يحجب مواقعه فورًا.
تخزين KV/الملفات الحقيقي ما زال يحتاج متغيرات `CLOUDFLARE_*` / `R2_*` (انظر [دليل الخلفية](backend.md)).
للعودة إلى السياسة المفتوحة القديمة (كل موقع يستطيع استخدام الخلفية) اضبط `BACKEND_GUEST_ACCESS=true`.

## الدليل العام

تعرض الصفحة الرئيسية (`/` و`/ar`) قسم **منشور من الفرق**: عنوان لكل فريق مدرج،
ثم شبكة بطاقات بالصور: صورة معاينة، وعنوان الصفحة، والرابط، وموعد انتهائه. فوقها
صفحة **مميزة** في بطاقة كبيرة (انظر `FEATURED_SITES` أدناه). البيانات نفسها متاحة كـ JSON عام في
`GET /api/directory` (تخزين مؤقت ٣٠ ثانية، CORS مفتوح):

```json
{ "generatedAt": "…", "featured": ["k3v9x2mq7a"],
  "teams": [ { "id": "t_…", "name": "Field notes",
    "sites": [ { "id": "k3v9x2mq7a", "title": "Weekly report",
      "url": "https://marsa.example.com/s/k3v9x2mq7a/", "createdAt": "…", "expiresAt": "…",
      "cover": "/covers/k3v9x2mq7a?v=1a2b3c4d5e" } ] } ] }
```

### صور الغلاف (صورة البطاقة)

لا تلتقط مرسى لقطات شاشة أبدًا ولا تنزّل أي شيء من مكان آخر. صورة البطاقة صورة
**موجودة أصلًا في رفعك**. تختار أول ما يتوفر من:

1. ملف باسم `cover.png` أو `cover.jpg` أو `cover.jpeg` أو `cover.webp` أو `cover.avif` أو `cover.gif`
   في جذر الموقع (بجانب `index.html`)؛
2. `<meta property="og:image" content="…">` (أو `twitter:image`) في `index.html`، إن كان
   يشير إلى ملف داخل الموقع (`img/share.png` أو `/s/<id>/img/share.png` أو الرابط الكامل لهذا
   الموقع كلها تعمل؛ الروابط إلى مواقع أخرى تُتجاهل)؛
3. أول `<img src="…">` في `index.html` يشير إلى ملف داخل الموقع.

يجب أن تكون الصورة PNG أو JPEG أو WebP أو AVIF أو GIF (وليس SVG) وبحجم 2 MB على الأكثر؛ صورة 1200×675 (16:9)
تبدو الأفضل. وإلا تعرض البطاقة صورة بديلة مرسومة بأول حرف من العنوان، بلون
الفريق. لضبط غلاف أو تغييره أضف `cover.png` إلى الموقع و**استبدل الملفات**
من لوحة الفريق (الرابط نفسه) أو أعد الرفع؛ تتحدث البطاقة خلال ٣٠ ثانية.

تُقدَّم الأغلفة من `GET /covers/<id>` فقط للمواقع المدرجة الحية، مع
`Content-Security-Policy: default-src 'none'; sandbox` و`nosniff` وفحص أن الملف فعلًا
من نوع الصورة الذي يدّعيه. الموقع المدرج بلا صورة صالحة يحصل على البديل المرسوم نفسه
كـ SVG مكتفٍ بذاته (`image/svg+xml`، بلا مراجع خارجية)، فلا ينكسر الرابط أبدًا؛ والمواقع
غير المدرجة أو غير الموجودة تُعيد `404`.

### الصفحة المميزة

`FEATURED_SITES=<id>[,<id>…]` (بيئة الخادم) يثبّت الصفحة الظاهرة في بطاقة **مميز**: أول
معرّف حي ومدرج. بدونه (أو عند زوال تلك الصفحات) تُميَّز أحدث صفحة مدرجة.
لا يُميَّز شيء عندما يكون الدليل فارغًا.

تظهر فقط المواقع الحية (غير المنتهية) للفرق التي فعّلت *الظهور في الدليل العام*. رفع الضيوف
ومفاتيح التعديل ومفاتيح الفرق والبصمات لا تُضمَّن أبدًا. الفرق بلا مواقع حية تُستبعد.

## API الإدارة

كل الاستدعاءات تحتاج `Authorization: Bearer $ADMIN_TOKEN`. المفاتيح تظهر فقط في استجابتي الإنشاء
والتدوير.

```bash
BASE=https://marsa.example.com; AUTH="Authorization: Bearer $ADMIN_TOKEN"

# List teams (with live site counts)
curl -s "$BASE/api/admin/teams" -H "$AUTH"

# Create a team with backend access, listed in the directory
curl -s -X POST "$BASE/api/admin/teams" -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"name": "Research desk", "backend": true, "directory": true}'
# => 201 { "team": { "id": "t_…", … }, "key": "marsa_team_…" }

# Rename, toggle backend or directory
curl -s -X PATCH "$BASE/api/admin/teams/t_abc12345" -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"backend": false}'

# New key (old one stops working)
curl -s -X POST "$BASE/api/admin/teams/t_abc12345/rotate" -H "$AUTH"

# Move the team to the trash for 7 days (type its name or id; add &sites=delete to also delete its sites)
curl -s -X DELETE "$BASE/api/admin/teams/t_abc12345?confirm=t_abc12345" -H "$AUTH"
```

تُحفظ الفرق في `DATA_DIR/teams.json` (تُكتب ذريًا، بصلاحية 600). انسخها احتياطيًا مع
بقية `DATA_DIR`.
