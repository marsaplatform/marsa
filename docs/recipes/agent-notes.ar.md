## الهدف

أن يعرف مسؤول المنصة بالمشكلات من الوكلاء الذين واجهوها، ومعها سياق كافٍ لإصلاحها (المرحلة والهدف والإصدار ونص الخطأ)، وأن يحصل الوكيل على رد.

## متى تتركون ملاحظة

- فشل نشر أو بناء، والخطأ لا يوضح طريقة الحل.
- وركر أو خادم MCP يفشل أثناء التشغيل بسبب المنصة (الربط، الأعلام، المفاتيح، الحصص).
- وصفة خاطئة أو قديمة أو غير واضحة: ملاحظة من نوع `recipe`، وهدفها اسم الوصفة المختصر (slug).
- لديكم **اقتراح**، أو تحتاجون من المسؤول تغيير شيء (حصة، تفعيل الوركرز، علم توافق).

لا تتركوا ملاحظة مع كل محاولة إعادة: ملاحظة واحدة لكل مشكلة، ومعها نص الخطأ.

## الطريقة

بمفتاح الفريق أو **أي** مفتاح وكيل (بلا صلاحية خاصة):

```sh
curl -s -X POST "$MARSA_URL/api/teams/<team>/notes" \
  -H "X-Team-Key: $MARSA_AGENT_KEY" -H "content-type: application/json" \
  -d '{
    "severity": "blocker",
    "stage": "deploy",
    "category": "bindings",
    "message": "PUT …/workers/morassel يعيد 400 \"binding NEWS: not a Worker of this team\" مع أن news تابع لنا.",
    "target": { "type": "worker", "id": "morassel" },
    "version": "4",
    "agent": "sanad-agent"
  }'
```

| الحقل | القيم |
|---|---|
| `severity` (مطلوب) | `info` أو `bug` أو `blocker` (يُنبّه جرس المسؤول) أو `suggestion` |
| `message` (مطلوب) | حتى 2000 حرف: ماذا فعلتم، وماذا حدث (الخطأ)، وماذا توقعتم |
| `stage` | `deploy` أو `build` أو `runtime` أو `recipe` أو `other` (الافتراضي) |
| `category` | تصنيف قصير، مثل `bindings` أو `upload` أو `keys` أو `mcp-recipe` |
| `target` | `{"type": "space" \| "worker" \| "mcp" \| "recipe", "id": "…"}` |
| `version` | معرّف النشر أو الإصدار (`4` أو SHA الـ commit) |
| `agent` | اسم الوكيل (الافتراضي: اسم المفتاح) |

## عبر MCP

عند الاتصال بمساحة: استدعوا أداة **`leave_note`** بالحقول نفسها، والهدف الافتراضي هو تلك المساحة.

## قراءة الردود

لقراءة ملاحظات فريقكم وحالتها (`open` أو `ack` أو `resolved`) وردود المسؤول:

```sh
curl -s "$MARSA_URL/api/teams/<team>/notes?status=open" -H "X-Team-Key: $MARSA_AGENT_KEY"
```

## القواعد

- **لا تضعوا أبدًا مفاتيح أو رموزًا أو كلمات مرور أو كوكيز في الملاحظة.** كل ما يشبهها يُستبدل بـ `[redacted]`، ومع ذلك غيّروا المفتاح المسرّب إن حدث ذلك.
- الحد 30 ملاحظة في الساعة لكل مفتاح، و16 ك.ب للطلب الواحد.
- تُعرض الملاحظات نصًا عاديًا، فلا يُعرض HTML أو markdown.
- يرى أعضاء الفريق ملاحظات فريقهم في **ملاحظات الوكلاء** في لوحة التحكم، ويرى مسؤول المنصة ملاحظات كل الفرق.
