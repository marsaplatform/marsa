## الهدف

أن يعمل الوكلاء فعليًا على مواقع الفريق ووركراته دون تسريب مفتاح أو فقدان بيانات أو تغيير لا يمكن التراجع عنه. انسخوا هذه القواعد في تعليمات الوكيل (موجّه النظام أو `AGENTS.md` أو قواعد المشروع).

## متى تستخدمها

- كلما حصل وكيل على مفتاح مساحات أو رمز MCP أو صلاحية نشر.
- قبل أي تغيير حي (نشر، حذف، تغيير مفتاح، DNS، نقل بيانات).

## الخطوات

1. **لا تطبع سرًّا ولا تكرره أبدًا**، لا في الطرفية ولا السجلات ولا ردود المحادثة ولا رسائل الـ commit ولا نص الـ PR ولا اللقطات. اقرأ المفاتيح من متغيرات البيئة أو ملف بصلاحية 600. إن احتجت إثبات وجود مفتاح فاعرض بادئته فقط (`marsa_agent_abc1…`).
   - صحيح: `curl -H "X-Team-Key: $MARSA_AGENT_KEY" …`
   - خطأ: `echo $MARSA_AGENT_KEY` أو `cat .env` أو `set -x` حول أوامر فيها مفاتيح.
2. **استعمل مفتاح وكيل محدد الصلاحيات وله انتهاء** لا مفتاح الفريق. اطلب من المالك رابط دعوة وكيل (الفريق ← مفاتيح الوكلاء ← ادعُ وكيلًا) بأقل صلاحيات تكفي المهمة، ومدة ٧ أو ٣٠ يومًا. يرى المالك آخر استخدام ويمكنه الإلغاء.
3. **الأسرار في مساحات لا في الكود.** أسرار الوركر في `secrets` (للكتابة فقط)، لا في `vars` ولا الكود ولا HTML ولا قيم KV.
4. **قبل أي تغيير حي: نسخة احتياطية، ثم ملاحظة رجوع، ثم التغيير.**
   - النسخة: نزّل ما ستغيّره (ZIP الموقع، مفاتيح KV، قائمة إصدارات الوركر).
   - ملاحظة الرجوع: فقرة فيها الأمر الدقيق للتراجع (مثلًا: أرجع الوركر `api` إلى v3 عبر `POST /api/teams/<team>/workers/api/rollback`).
   - غيّر شيئًا واحدًا كل مرة، ثم تحقق (رموز الحالة، `/health`، `initialize`) وبلّغ.
5. **لا بيانات خاصة.** المواقع المنشورة وKV الموقع عامة لمن معه الرابط. لا تنشر بيانات شخصية أو قوائم اتصال أو وثائق داخلية أو بيانات دخول.
6. **ابقَ داخل فريقك.** لا تلمس مواقع أو وركرات فرق أخرى ولا إعدادات المنصة ولا سكربتات لم تنشئها مساحات. إن احتجت صلاحية أكبر فتوقف واسأل إنسانًا.
7. **بلّغ بصدق:** ما الذي غيّرته، وما الذي تحققت منه، وما الذي فشل، وما الذي لم تفعله.

## القالب

انسخوه في تعليمات الوكيل:

```md
## قواعد مساحات مرسى
- المفاتيح: من $MARSA_AGENT_KEY فقط. لا تطبع ولا تكرر ولا تسجّل أي مفتاح أو رمز أو كلمة مرور. البادئة فقط.
- النطاق: الفريق <slug> فقط. لا فرق أخرى ولا إعدادات المنصة ولا وركرات خارج مساحات.
- قبل أي تغيير حي: نسخة احتياطية، ثم أمر الرجوع مكتوبًا، ثم تغيير واحد وتحقق.
- الأسرار في secrets الوركر فقط، لا في الكود ولا vars ولا HTML ولا KV.
- لا تنشر بيانات شخصية أو خاصة؛ الصفحات وKV عامة.
- إن احتاج الأمر صلاحية أكبر أو كان لا رجعة فيه: توقف واسأل.
- التقرير النهائي: التغييرات، التحقق، الإخفاقات، الرجوع، وما تبقى.
```

## قائمة التحقق قبل النشر

- [ ] المفتاح المستعمل مفتاح وكيل بالصلاحيات اللازمة فقط وله انتهاء.
- [ ] لا يظهر أي سر في سجل الأوامر أو المخرجات أو الكود أو المتغيرات أو الـ commit أو التقرير.
- [ ] توجد نسخة احتياطية وأمر الرجوع مكتوب.
- [ ] جرى التحقق الحي بعد التغيير.
- [ ] لم يُنشر شيء خاص.

## أخطاء شائعة

- **مخرجات التصحيح** (`curl -v` و`set -x`) تطبع ترويسة `Authorization`.
- **لصق ملف `.env` في المحادثة** «للتأكد».
- **مفتاح الفريق في أسرار CI** تتشاركه مهام كثيرة: اجعلوا لكل مهمة مفتاح وكيل منفصلًا.
- **«إصلاح سريع» مباشرة في الإنتاج** بلا ملاحظة رجوع.
- **وضع رمز في صفحة منشورة** «للعرض فقط»: أي أحد يقرأ مصدر الصفحة.
- **ترك فريق أو موقع أو وركر تجريبي** بعد التجربة: نظّفوا.
